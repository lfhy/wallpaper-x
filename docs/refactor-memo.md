 # Refactor Memo (Concise)

## Pre-Change Requirements
# 核心协作规则（必须严格遵守）
1. 任何修改前先做前置检查：是否已有实现、是否影响现有功能，确保无破坏性改动。
2. 必须先定位根因，再输出代码；禁止打补丁、禁止堆代码、禁止治标不治本。
3. 输出顺序固定：先给执行方案 → 说明修改位置 → 技术原理 → 下一步计划 → 确认后再写代码。
4. 修复原则：删除错误逻辑 + 清理废弃代码 + 走正确路径，不保留备用/冗余代码。
5. 代码设计目标：可维护、无重复、简洁、低耦合、易调试、不牵连其他功能。
6. 技术方案必须采用行业成熟标准，尤其遵循视频壁纸类 App 的稳定性最佳实践。
7. 如果需求已完成、无法实现或需要用户提供信息，必须明确告知，不模糊处理。
8. 每次代码改动后必须保证编译成功，并提供最小回归验证步骤。
9. 每一步输出必须包含：可执行验证方法 + 复现步骤 + 预期正确结果。
10. 尽量合并相关改动，减少碎片化交互，不重复消耗上下文。
# 项目架构规则（强制）
11. 严格遵循单一渲染真源原则：同一功能只保留一条有效 UI 路径，禁止双实现长期并存。
12. 每阶段必须定义性能门槛并验证：冷启动速度、首屏可交互时间、大图库滚动帧率。
13. 全局状态唯一来源：WallpaperManager，禁止 UI 层复制业务状态。
14. 模块迁移完成后立即删除旧代码、旧文件、无效引用，防止回归走旧路径。
15. 代码结构按领域拆分：播放、图库、缓存、UI、系统集成，禁止多领域混合堆在一个文件。
16. 每阶段只修改一个主领域/模块，不跨模块连锁重构，确保可回滚、可定位。
17. 文件组织按领域拆分，不按函数/细模块拆分，不创建过度细碎的文件。
# 专家行为规则
18. 你是 macOS 专业开发专家，必须主动指出用户策略问题、风险点并给出建议，不盲目服从。
19. 设计优先级：性能 > 流畅度 > 用户体验 > 逻辑合理性 > 代码简洁。
20. 不把时间浪费在影响极小、无感知的细节问题上，聚焦高价值问题。
# 代码规范
21. 注释只写意图、约束、依赖、风险点，不描述代码本身；重点标注高风险入口、状态桥接、持久化、易回归点。
22. 每个领域文件顶部写清职责；关键方法写清用途，防止未来误删误改。

## Stable Results

这些结论默认视为已完成，不要再回退重做，除非出现新回归。

1. 播放/daemon/状态判定已统一为单一路径，主流程不再走旁路入口。
2. 导入、缩略图、静帧、最近使用、持久化都已做过降载与去重，避免重复写盘和重复刷新。
3. AppKit 迁移已收口到单渲染真源，旧 SwiftUI 路径和过渡入口已删除。
4. 设置页、工具栏、主容器、侧边栏、网格、QuickLook 都已迁移到 AppKit 原生链路。
5. 侧边栏标签顺序已可持久化，默认四个标签也可手动排序。
6. 侧边栏标签拖放排序已完成，当前采用原生 `NSOutlineView` live reorder：拖起整行、原位留空、其他行平滑让位，拖拽期间隐藏选中高亮。
7. 缩略图/静帧生成改为后台串行两阶段，导入不再同步阻塞主线程。
8. 导出/导入个人设置、SQLite 索引迁移、重置为首次安装状态都已完成。
9. 填充模式切换（保持原尺寸↔填充屏幕）已完成，动画方案：daemon 统一用 `resizeAspectFill`，通过 CATransaction 隐式 frame 动画在 layer frame 大小之间平滑过渡，视频就绪后在 `activatePreparedPlayer` 里无动画设置精确 frame，切换时读 presentation layer 旧 frame 作为动画起点。
10. 侧边栏每个列表独立排序状态已完成：`SortState(mode, ascending)` 存于 `WallpaperManager.perSelectionSortStates: [String: SortState]`，key = `WallpaperSelectionContext.scrollPersistenceKey`，持久化到 `UserDefaults["PerSelectionSortStates"]`；`sortedWallpapers(_:selectionKey:)` 按 key 读取对应状态；工具栏读写当前列表的独立状态。
